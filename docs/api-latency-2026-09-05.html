What changed since the last run

Measured the same way, on the same machine, against the same database. Anything that moved by less than 12 % or 8 ms is treated as noise and left out — two runs on a workstation differ by that much for reasons that have nothing to do with the code. Endpoints marked fs survey the filesystem and are timed once with no warm-up, so what moved there is usually the state of the disk and the caches rather than the code.

How this was measured

Every GET route in angular/api-spec.json, called against a development server on this workstation with a database on the same machine. Two warm-up requests, then 7 timed ones; the number quoted is the median. Path arguments are filled from the collection the route belongs to, so an id used in a request is an id that exists — otherwise half the sample would be a 404 being timed.

Routes that survey the filesystem are timed once rather than sampled and marked fs; they are doing work rather than answering a question, and averaging them in would misrepresent the rest. Writes are not timed at all: that would mean creating and destroying an entity per sample, which measures the fixture rather than the endpoint.

The absolute values do not travel — production has different hardware, a different PHP setup, and a network in between. The shape does: what dominates, what is an outlier, and which direction things moved between runs. This run answered 24.8 MB in total across 163 endpoints, with none failing.
